# UI Matrix Template

Goal: systematically test real user-facing UI behavior through actual interactions across desktop, browser, demo, and responsive surfaces.

Use this template as the control file for a long-horizon UI regression pass. Keep the loop here, and load only the active checklist item file plus the minimum test/app context needed.

## Loop

1. Pick the next unchecked checklist item below and open its linked file.
2. Load only the relevant UI, test, fixture, and app-launch context for that item.
3. Define or select the product target, data-state matrix, page or feature, initial data setup, user interaction, expected UI result, expected data/state result, cross-page consistency checks, priority, test type, screenshots/captures required, and edge-case notes.
4. Exercise the target through real user interactions, not route-load-only checks. Use navigation, clicks, forms, drawers, modals, scrolling, resizing, reloads, screenshots, and captures as applicable.
5. Fix confirmed UI, state, layout, or missing-coverage gaps that are supported by evidence.
6. Prefer automated regression coverage where practical; use visual/manual evidence when the behavior is layout, screenshot, Electron geometry, or responsive specific.
7. Verify with the most relevant UI test, smoke test, screenshot, capture, build, or focused check. If a check cannot be run, record why and use the closest available verification.
8. Update docs or test metadata only when behavior, coverage strategy, commands, screenshots, or known constraints changed.
9. Review `git status`; stage only files that belong to the completed UI/test batch with targeted `git add` commands. Leave unrelated user changes untouched.
10. Record coverage added, interactions tested, failures fixed, screenshots/captures, commands run, changed/staged files, and remaining risk.
11. Mark the checklist item `[x]` here when it is complete for this pass.
12. Continue until every item is checked.

After every item is `[x]`, start a fresh pass by resetting the checklist to unchecked if the goal is continuing. Repeat until a fresh pass finds no actionable UI gaps.

Stop when remaining gaps are speculative, duplicate coverage, product decisions, user-input-dependent, or blocked by unavailable verification.

Desktop receives the deepest coverage. Dependent-state workflows come first, followed by fresh-state protection, autogenerated populated coverage, browser parity, demo browser behavior, and mobile/responsive stability.
