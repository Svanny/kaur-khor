## Banji សម្រាប់អ្វី

Banji សម្រាប់ក្រុមដែលចង់បានកន្លែងធ្វើការស្តុកដែលអនុវត្តបានលើម៉ាស៊ីនតែមួយ ដោយមិនពឹងផ្អែកលើ back office នៅលើ cloud។ វាត្រូវបានបង្កើតឡើងសម្រាប់៖

- រក្សាកាតាឡុក SKU និងសេវាកម្មដែលកំពុងប្រើ
- កត់ត្រាការផ្លាស់ប្តូរស្តុក និងសញ្ញាសេវាកម្មនៅពេលវាកើតឡើង
- មើលថា អ្វីត្រូវធ្វើបន្ទាប់
- ពិនិត្យសញ្ញាផែនការ និងប្រសិទ្ធភាពក្នុងម៉ាស៊ីនតែមួយ

Banji មិនមានគោលបំណងធ្វើជាដូចខាងក្រោមទេ៖

- ERP ពេញលេញ
- SaaS សម្រាប់អ្នកប្រើច្រើនដែលបង្ហោះលើ cloud
- workflow builder ទូទៅ សម្រាប់គ្រប់ inventory model

ផលិតផលនេះមានទិសដៅច្បាស់។ បទពិសោធន៍ល្អបំផុតកើតឡើង នៅពេលអ្នកប្រើកាតាឡុក ការកត់ត្រាអាប់ដេត និងលំហូរការងារវិភាគដែលមានស្រាប់ ជាមួយគ្នា។

## របៀបដែលលំហូរការងារសំខាន់ភ្ជាប់គ្នា

ក្រុមភាគច្រើននឹងប្រើ Banji តាមលំដាប់នេះ៖

1. សង់កាតាឡុកក្នុង **កាតាឡុក** ដោយបង្កើត SKU និងសេវាកម្ម។
2. កត់ត្រាស្ថានភាពពិតមួយក្នុង **កត់ត្រាការអាប់ដេត**។
3. ពិនិត្យការងារតាមដានភ្លាមៗក្នុង **ទិដ្ឋភាពទូទៅ**។
4. មើលប្រវត្តិដែលបានរក្សាទុកក្នុង **កំណត់ហេតុ**។
5. ពិនិត្យសញ្ញាអាទិភាព និងផែនការក្នុង **ប្រសិទ្ធភាព** និង **ការវិភាគ**។
6. កែប្រែចំណង់ចំណូលចិត្ត ការនាំចេញ ការបម្រុងទុក និងការគ្រប់គ្រងផែនការក្នុង **ការកំណត់**។

បើអ្នកទើបចាប់ផ្តើម៖

1. បង្កើត SKU ដំបូង។
2. បន្ថែម service bundle ដែលអាស្រ័យលើ SKU ទាំងនោះ។
3. ដំណើរការការកត់ត្រាការអាប់ដេតលើកដំបូង។
4. ត្រឡប់ទៅទិដ្ឋភាពទូទៅវិញ ដើម្បីមើលថា Banji អាចសន្និដ្ឋានអ្វីពីទិន្នន័យដែលបានរក្សាទុក។

## ការរុករក និងការគ្រប់គ្រងសកល

navigation ខាងឆ្វេងរបស់ Banji គឺជាវិធីសំខាន់សម្រាប់ផ្លាស់ទីក្នុងផលិតផល។ ទិសដៅកម្រិតលើមាន៖

- **ទិដ្ឋភាពទូទៅ**៖ ជំហានប្រតិបត្តិការបន្ទាប់ និងជួរបច្ចុប្បន្ន
- **កត់ត្រាការអាប់ដេត**៖ លំហូរការងារដែលមានការណែនាំសម្រាប់កត់ត្រាអាប់ដេតថ្មី
- **ប្រសិទ្ធភាព**៖ តារាងអាទិភាព និងផ្ទៃសម្រាប់សម្រេចចិត្តផ្អែកលើប្រសិទ្ធភាព
- **កាតាឡុក**៖ កំណត់ត្រា SKU និងសេវាកម្ម
- **ការវិភាគ**៖ ផ្ទៃពន្យល់ជ្រាលជ្រៅសម្រាប់ SKU និងសេវាកម្ម
- **កំណត់ហេតុ**៖ ប្រវត្តិការអាប់ដេតដែលបានរក្សាទុក
- **បណ្ណសារ**៖ ធាតុកាតាឡុកដែលបានដាក់បណ្ណសារ
- **ការកំណត់**៖ ចំណង់ចំណូលចិត្តក្នុងម៉ាស៊ីន ការនាំចេញ សកម្មភាពបម្រុងទុក និងស្តារឡើងវិញ និងការគ្រប់គ្រងផែនការ

អាកប្បកិរិយាសកលដែលគួរដឹង៖

- **Collapsed navigation** លាក់អត្ថបទផ្នែក ប៉ុន្តែនៅតែរក្សាទិសដៅទាំងអស់ឲ្យប្រើបាន។
- **Search / Command palette shortcut (`Cmd/Ctrl + K`)** បើក command palette យ៉ាងរហ័ស។
- **Loading states** ជាទូទៅមានន័យថា Banji កំពុងបើក workspace ក្នុងម៉ាស៊ីន ធ្វើបច្ចុប្បន្នភាពទិន្នន័យដែលបានរក្សាទុក ឬគណនាវិភាគក្នុងម៉ាស៊ីនឡើងវិញ។
- **Tooltips និង helper copy** ពន្យល់ label និង metric ជាច្រើន។ អ្នកអាចបន្ថយវាបានក្នុង Settings បើចង់បាន interface ស្ងប់ជាងមុន។

## ទិដ្ឋភាពទូទៅ

### គោលបំណង

ទិដ្ឋភាពទូទៅ គឺជាកន្លែងធ្វើការ "ខ្ញុំគួរធ្វើអ្វីបន្ទាប់?" របស់ Banji។ វាជាចំណុចចាប់ផ្តើមល្អបំផុត បន្ទាប់ពីអ្នកបានបង្កើតកាតាឡុក និងរក្សាទុកអាប់ដេតយ៉ាងហោចណាស់មួយ។

### ពេលណាគួរប្រើ

ប្រើទិដ្ឋភាពទូទៅ នៅពេលអ្នកចង់៖

- មើលបញ្ហាស្តុក ឬសម្ពាធបញ្ជាទិញបន្ថែមដែលខ្លាំងជាងគេមុន
- ចាប់ផ្តើមវគ្គអាប់ដេតបន្ទាប់
- ពិនិត្យសកម្មភាពថ្មីៗ ដោយមិនចាំបាច់ចូលទៅប្រវត្តិពេញ
- បើក SKU ឬធាតុក្នុងជួរបន្ទាប់ដែលត្រូវពិនិត្យ

- ពិនិត្យអាទិភាពបញ្ជាទិញបន្ថែម

- ត្រូវបើកអ្វីបន្ទាប់

ផ្ទាំងនេះសង្ខេបអំពីអ្វីដែលបានផ្លាស់ប្តូរថ្មីៗនៅទូទាំងអាប់ដេតដែលបានរក្សាទុក។ ប្រើវា នៅពេលអ្នកត្រូវការបរិបទ មុនពេលសម្រេចថា តើគួរបើក Logs ឬចាប់ផ្តើមអាប់ដេតមួយទៀត។

#### សកម្មភាពរហ័ស

វាជាផ្លូវកាត់ទៅកាន់លំហូរការងារសំខាន់ៗ ដូចជា បើកកាតាឡុក ឬចាប់ផ្តើមវគ្គអាប់ដេតថ្មី។ វាមានប្រយោជន៍ នៅពេលអ្នកដឹងរួចហើយថា ត្រូវធ្វើអ្វី ហើយមិនចាំបាច់ប្រើផ្នែកផ្សេងទៀតនៃទំព័រ។

### ការគ្រប់គ្រង និងប៊ូតុងសំខាន់ៗ

- **Queue filters** បង្រួមជួរទៅប្រភេទបញ្ហាមួយ ដូចជា "បញ្ជាទិញឥឡូវនេះ" ឬ "តាមដានថ្ងៃនេះ"។
- **Search** បង្រួម task និង entity ដែលមើលឃើញ ដោយមិនប្ដូរទិន្នន័យដែលបានរក្សាទុក។
- **Review SKU** បើកទំព័រលម្អិតរបស់ SKU សម្រាប់ពិនិត្យជ្រាលជ្រៅ។
- **Open catalog / Open logs / Start update session** ជាផ្លូវកាត់លំហូរការងារ មិនមែនជាស្ថានភាពទិន្នន័យផ្សេងទៀតទេ។

### កំហុសដែលជាញឹកញាប់

- ប្រើទិដ្ឋភាពទូទៅជំនួស Record update។ ទិដ្ឋភាពទូទៅជួយអ្នកជ្រើសការងារ ប៉ុន្តែមិនកត់ត្រាភស្តុតាងថ្មីទេ។
- យក metric ផ្ទៃខាងក្រោយធ្វើជាផ្ទៃសម្រេចចិត្តសំខាន់។ ជួរ និងផ្ទាំងណែនាំគួរតែមកមុនជាទូទៅ។
- រំពឹងថានឹងមានអាទិភាពមានប្រយោជន៍ មុនពេលមានធាតុកាតាឡុកដំបូង ឬអាប់ដេតដែលបានរក្សាទុកលើកដំបូង។

## កត់ត្រាការអាប់ដេត

### គោលបំណង

កត់ត្រាការអាប់ដេត គឺជាលំហូរការងារដែលមានការណែនាំសម្រាប់រក្សាទុក operational snapshot ថ្មីមួយ។ នេះជាកន្លែងដែល Banji រៀនថា អ្វីបានផ្លាស់ប្តូរនៅក្នុងពិភពពិត។

### ពេលណាគួរប្រើ

ប្រើកត់ត្រាការអាប់ដេត នៅពេល៖

- ចំនួនស្តុកបានផ្លាស់ប្តូរ
- មានការបញ្ជាទិញត្រូវបានដាក់
- ទំនិញត្រូវបានទទួល
- សេវាមួយត្រូវបានរារាំង ឬលែងរារាំង
- តម្លៃបានផ្លាស់ប្តូរ
- អ្នកចង់ឲ្យការវិភាគរបស់ Banji ឆ្លុះបញ្ចាំងស្ថានភាពបច្ចុប្បន្ន

### របៀបដែលជំហានដំណើរការ

Banji នាំអ្នកឆ្លងកាត់ប្រាំជំហាន។

#### 1. ព័ត៌មានលម្អិតអំពីការអាប់ដេត

នេះជាជំហានបរិបទ។ វាកត់ត្រា៖

- ពេលវេលាដែលបានសង្កេត
- កំណត់ចំណាំអំពីការអាប់ដេត
- សញ្ញា sales pattern / regime បើអ្នកចង់ពិពណ៌នាអំពីអាកប្បកិរិយាតម្រូវការទូទៅ

ប្រើជំហាននេះ ដើម្បីពន្យល់លក្ខខណ្ឌជុំវិញការអាប់ដេត ជាពិសេស បើថ្ងៃនេះខុសពីធម្មតា។

#### 2. បន្ថែមចំនួនស្តុក

ជំហាននេះកត់ត្រាព័ត៌មានស្តុកកម្រិត SKU។ អាស្រ័យលើធាតុ និងស្ថានភាពលំហូរការងារបច្ចុប្បន្ន អ្នកអាចកត់ត្រា៖

- បរិមាណដែលបានរាប់បច្ចុប្បន្ន
- សញ្ញាបញ្ជាទិញ
- សញ្ញាទទួលទំនិញ
- ស្ថានភាពរារាំង ឬអស់ស្តុក

stock view filter ប្តូរថា អ្នកឃើញកាតាឡុកច្រើនប៉ុនណា៖

- **Priority** បង្ហាញជួរសំខាន់ៗមុន
- **Counted** ផ្តោតលើជួរដែលបានប៉ះរួចហើយក្នុង draft
- **All** បង្ហាញ SKU ដែលមានសិទ្ធិទាំងអស់

#### 3. បន្ថែមការអាប់ដេតសេវាកម្ម

ជំហាននេះកត់ត្រាសញ្ញាផ្នែកសេវាកម្ម ដូចជា៖

- ការផ្លាស់ប្តូរតម្លៃ
- ស្ថានភាពរារាំង ឬអស់ស្តុក

ប្រើវា នៅពេលសេវាកម្មមួយទទួលផលប៉ះពាល់ ទោះបីមិនមានការរាប់ SKU ថ្មីនៅពេលដូចគ្នាក៏ដោយ។

#### 4. រៀបលំដាប់ការលក់ថ្មីៗ

ជំហាននេះកត់ត្រាលំដាប់លក់ថ្មីៗសម្រាប់សេវាកម្ម និងធាតុលក់រាយ។ Ranking ជួយ Banji ឲ្យយល់ថា អ្វីកំពុងលក់មុន មិនមែនគ្រាន់តែមានអ្វីនៅក្នុងកាតាឡុកទេ។

ប្រើ ranking នៅពេល៖

- លំដាប់លក់បានផ្លាស់ប្តូរ
- អាទិភាពតម្រូវការបានផ្លាស់ទី
- អ្នកចង់ឲ្យការវិភាគរបស់ Banji ឆ្លុះបញ្ចាំងអ្វីដែលបានផ្លាស់ទីមុននៅក្នុងពិភពពិត បានល្អជាងមុន

#### 5. ពិនិត្យឡើងវិញ

នេះជាជំហានបញ្ជាក់ចុងក្រោយ មុនពេលរក្សាទុក។ ប្រើវា ដើម្បីផ្ទៀងផ្ទាត់ថា៖

- ពេលវេលាសង្កេតត្រឹមត្រូវ
- SKU និងសេវាកម្មត្រឹមត្រូវត្រូវបានអាប់ដេត
- ការរៀបលំដាប់ និងបរិបទមានហេតុផល
- មិនមានអ្វីចៃដន្យនៅសល់ក្នុង draft

### ការគ្រប់គ្រង និងប៊ូតុងសំខាន់ៗ

- **Next / Back** ផ្លាស់ទីរវាងជំហាន ដោយមិនបញ្ចប់ session ភ្លាមៗ។
- **Save** commit ការអាប់ដេត ហើយធ្វើឲ្យវាអាចប្រើបានក្នុង Overview, Logs, Performance និង Analysis។
- **Undo** ត្រឡប់ការផ្លាស់ប្តូរដែលមិនទាន់រក្សាទុក ក្នុងបរិបទ session បច្ចុប្បន្ន។
- **Delete / discard draft** លុប draft កំពុងដំណើរការ ឬបោះបង់លំហូរកែប្រែបច្ចុប្បន្ន។
- **Priority / Counted / All** ប្តូរថា អ្នកឃើញជួរស្តុកណា មិនមែនអ្វីដែលត្រូវរក្សាទុកទេ។
- **Blocked / Stockout** អនុញ្ញាតឲ្យអ្នកសម្គាល់ការរំខានដោយផ្ទាល់ ជំនួសឲ្យបង្កប់ន័យពីស្តុកទាបតែប៉ុណ្ណោះ។
- **Sales pattern help** និងប៊ូតុងជំនួយផ្សេងទៀត ពន្យល់ពាក្យដែលត្រូវបានប្រើក្នុងលំហូរការងារនេះ។

### កំហុសដែលជាញឹកញាប់

- រំលង observed time ហើយទុក timestamp មិនត្រឹមត្រូវ។
- កត់ត្រាតែបរិមាណស្តុក ប៉ុន្តែភ្លេចសញ្ញាបញ្ជាទិញ ទទួលទំនិញ ឬសេវាកម្មដែលត្រូវគ្នា។
- ដាក់ ranking ដោយមិនយកចិត្តទុកដាក់។ Ranking គួរឆ្លុះបញ្ចាំងលំដាប់លក់ពិតថ្មីៗ មិនមែនអាទិភាពអនាគតដែលចង់បានទេ។
- រក្សាទុក draft ដែលលាយបញ្ចូលព្រឹត្តិការណ៍ពិតពីរផ្សេងគ្នា ចូលក្នុងអាប់ដេតតែមួយ។

## ប្រសិទ្ធភាព

### គោលបំណង

ប្រសិទ្ធភាព បម្លែងលទ្ធផលផែនការក្នុងម៉ាស៊ីនរបស់ Banji ឲ្យក្លាយជាតារាង និង board ដែលផ្អែកលើសកម្មភាព។ វាសម្រាប់ការដាក់អាទិភាព មិនមែនសម្រាប់ការបញ្ចូលទិន្នន័យ raw ទេ។

### ពេលណាគួរប្រើ

ប្រើប្រសិទ្ធភាព នៅពេលអ្នកចង់៖

- ប្រៀបធៀប SKU និងសេវាកម្មតាមរយៈរយៈពេលខ្លី ឬមធ្យម
- ពិនិត្យសញ្ញា cash, drag, price watch និង recovery ជាមួយគ្នា
- យល់ថា Banji គិតថា នឹងមានអ្វីកើតឡើងបន្ទាប់ បើមិនមានអ្វីផ្លាស់ប្តូរ

- ត្រូវផ្លាស់ទីអ្វី
- ហេតុអ្វីឥឡូវនេះ
- ផលប៉ះពាល់ដែលរំពឹងទុក

### ទិដ្ឋភាពសំខាន់ៗ

#### Heatmap

- **Show optional help**៖ រក្សា ឬលាក់ explanatory copy និង tooltip បន្ថែម

- probability gates

- **SKU**៖ ធាតុដែលមានស្តុក ត្រូវបានតាមដានដោយផ្ទាល់ក្នុង Banji

- **Blocked**៖ ធាតុ ឬសេវាកម្ម មិនអាចផ្លាស់ទីតាមធម្មតាបាន ដោយសារបញ្ហាប្រតិបត្តិការ
- **Regime / sales pattern**៖ សញ្ញាប្រាប់អំពីលំនាំតម្រូវការទូទៅ ជុំវិញការអាប់ដេត
- **Workspace summary**៖ ទិដ្ឋភាពសរុបក្នុងម៉ាស៊ីនរបស់ Banji ដែលបង្កើតពី observation ដែលបានរក្សាទុក
- **Archive**៖ កំណត់ត្រាកាតាឡុកដែលមិនសកម្ម ត្រូវបានរក្សាទុកក្រៅ workspace សកម្ម ប៉ុន្តែរក្សាប្រវត្តិទុក

## សំណួរញឹកញាប់

### តើខ្ញុំត្រូវចាប់ផ្តើមនៅទិដ្ឋភាពទូទៅទេ?

មិនចាំបាច់ទេ។ បើអ្នកកំពុងរៀបចំ Banji ជាលើកដំបូង សូមចាប់ផ្តើមនៅកាតាឡុក។ ទិដ្ឋភាពទូទៅនឹងមានប្រយោជន៍ បន្ទាប់ពីមានធាតុកាតាឡុកយ៉ាងហោចណាស់មួយ និងអាប់ដេតដែលបានរក្សាទុកយ៉ាងហោចណាស់មួយ។

### តើភាពខុសគ្នារវាង Overview, Performance និង Analysis ជាអ្វី?

- **Overview** ប្រាប់អ្នកថា អ្វីទំនងជាត្រូវយកចិត្តទុកដាក់បន្ទាប់។
- **Performance** រៀបចំការប្រៀបធៀបផ្អែកលើសកម្មភាព និងតារាងអាទិភាព។
- **Analysis** ពន្យល់សញ្ញា និងចន្លោះពេលខាងក្រោម ឲ្យបានលម្អិតជាងមុន។

### ហេតុអ្វីបានជា Analysis ទទេ ឬមានកម្រិត?

ជាទូទៅ ព្រោះអ្វីមួយក្នុងចំណោមខាងក្រោមនេះ នៅមិនទាន់មាន៖

- កាតាឡុកដែលមានទិន្នន័យ
- អាប់ដេតដែលបានរក្សាទុកលើកដំបូង
- ការផ្ទុកព័ត៌មានលម្អិតក្នុងម៉ាស៊ីនគ្រប់គ្រាន់ សម្រាប់ទិដ្ឋភាពបច្ចុប្បន្ន

### តើភាពខុសគ្នារវាង Logs និង Archive ជាអ្វី?

- **Logs** រក្សាទុកប្រវត្តិអាប់ដេតដែលបានរក្សាទុក។
- **Archive** រក្សាទុក SKU និងសេវាកម្មដែលមិនសកម្ម។

វាដោះស្រាយបញ្ហាផ្សេងគ្នា។ Logs គឺជាសកម្មភាពប្រវត្តិ ខណៈ Archive គឺជាស្ថានភាពកាតាឡុកមិនសកម្ម។

### តើមានអ្វីកើតឡើង បើខ្ញុំដាក់ SKU ឬសេវាកម្មមួយចូលបណ្ណសារ?

វានឹងឈប់បង្ហាញនៅក្នុង workspace សកម្ម ដូចជា Catalog និង planning surface ប៉ុន្តែវានៅតែជាផ្នែកមួយនៃប្រវត្តិរបស់ Banji រហូតដល់អ្នកស្ដារវាវិញ។

### តើភាពខុសគ្នារវាង export និង backup ជាអ្វី?

- **Export** ទាញយកទិន្នន័យជា file format ដែលអាចប្រើបាន ដូចជា Excel, CSV ឬ JSON។
- **Backup** បង្កើត snapshot ក្នុងម៉ាស៊ីន ដែលបង្កើតឡើងសម្រាប់ស្ដារ workspace នៅពេលក្រោយ។

ប្រើ export សម្រាប់ការវិភាគ ឬចែករំលែក។ ប្រើ backup សម្រាប់ការស្ដារឡើងវិញ។

### តើខ្ញុំអាចកែប្រែ report ដែលបានរក្សាទុកបានទេ?

បាន។ Logs អនុញ្ញាតឲ្យបើកអាប់ដេតដែលបានរក្សាទុកឡើងវិញសម្រាប់កែប្រែ។ បើ report មួយខុស សូមកែវា នៅពេលអាចធ្វើបាន ជំនួសឲ្យលុបវាភ្លាមៗ។

### តើពេលណាខ្ញុំគួរប្រើ sales pattern ឬ regime hint?

ប្រើវា នៅពេលការអាប់ដេតបច្ចុប្បន្ន កើតឡើងក្រោមលំនាំតម្រូវការដែលសម្គាល់ឃើញច្បាស់ ដូចជា ការឡើងខ្លាំងមិនធម្មតា ការធ្លាក់ចុះ ឬការផ្លាស់ប្តូរមានន័យផ្សេងទៀត។ វាផ្ដល់បរិបទបន្ថែមឲ្យ Banji ជុំវិញការអាប់ដេត។

### ហេតុអ្វីបានជាមាន tooltip ច្រើនម្ល៉េះ?

Banji ដាក់ explanatory copy ព្រោះពាក្យជាច្រើនក្នុងផែនការ និងប្រសិទ្ធភាព ត្រូវបានបង្រួមដោយចេតនា។ បើអ្នកស្គាល់លំហូរការងារល្អរួចហើយ អ្នកអាចបន្ថយ optional help ក្នុង Settings។

### តើ Banji អាចដំណើរការដោយគ្មានអ៊ីនធឺណិតបានទេ?

Banji ត្រូវបានរចនាឡើងជា local-first desktop workspace។ មុខងារក្នុងម៉ាស៊ីន និងការផ្ទុកទិន្នន័យក្នុងម៉ាស៊ីន គឺជាស្មារតីសំខាន់របស់ផលិតផល។

### តើខ្ញុំគួរធ្វើអ្វី មុនពេលសម្អាតទិន្នន័យក្នុងម៉ាស៊ីនបច្ចុប្បន្ន?

បង្កើត backup snapshot មួយជាមុនសិន លុះត្រាតែអ្នកប្រាកដថា អ្នកចង់កំណត់ឡើងវិញស្អាតៗ ហើយមិនត្រូវការទិន្នន័យ workspace បច្ចុប្បន្នទៀតទេ។
