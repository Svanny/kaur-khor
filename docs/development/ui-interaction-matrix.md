# UI Interaction Matrix

The UI interaction matrix is a local Playwright regression suite for real user
flows. It is separate from the performance benchmark suite: benchmarks measure
latency targets, while the UI matrix checks user-facing behavior, layout
integrity, state propagation, and runtime stability.

Run the full matrix:

```bash
pnpm ui:matrix
```

Run a focused target:

```bash
pnpm ui:matrix:desktop
pnpm ui:matrix:web
pnpm ui:matrix:mobile
```

Additional Playwright flags can be appended:

```bash
pnpm ui:matrix:desktop -- --grep dependent
```

The desktop target builds the Electron app and `apps/desktop-core` before
launching isolated Electron sessions. Browser and mobile targets start the local
web app through the UI-matrix Playwright Vite server port.

## Data States

The matrix is organized by data state, not just by route:

- Fresh state: an empty isolated workspace. It covers onboarding, empty routes,
  empty tables/charts, disabled controls, route guards, and first-run stability.
- Autogenerated state: deterministic generated fixtures. It covers populated
  routes, detail pages, filters, drawers, charts, and representative screenshots.
- Dependent state: organic UI updates from a sparse workspace. It creates catalog
  entries, records updates, reloads, and checks that visible pages agree with the
  bridge-level data state.

Desktop is the primary target and owns the deepest dependent-state coverage.
Browser app, demo browser, and responsive/mobile tests cover parity, local-first
controls, route stability, and layout integrity.

## Artifacts

Each run writes Playwright artifacts under:

```text
ui-matrix-results/playwright-artifacts
```

Scenario screenshots are attached to the Playwright test output under each
test's `captures/` directory. The suite intentionally stores screenshots as
diagnostic captures only. It does not use pixel baselines in this phase.

## Guardrails

Every matrix scenario should use shared helpers from `ui-matrix/helpers` for:

- console, page-error, and request-failure collection
- screenshot capture
- document-level overflow checks
- broken numeric/date text checks such as `NaN` or `Invalid Date`
- hash-route navigation and back/forward checks
- isolated desktop data directories and generated fixtures

Prefer role and label selectors. Add product `data-testid` or `data-slot`
attributes only when the UI does not expose a stable accessible selector.

## Adding Cases

Add scenario metadata in `ui-matrix/matrix-cases.ts` before adding a new scenario
or expanding an existing one. Each case records the product target, data-state
matrix, feature area, setup, interaction, expected UI result, expected data
result, consistency checks, priority, test type, captures, and edge notes.

When expanding dependent-state coverage, prefer real UI actions first and bridge
probes second. The bridge should confirm state consistency after the UI action,
not replace the UI action being tested.
